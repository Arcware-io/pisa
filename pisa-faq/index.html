    If anything here disagrees with pisa --help, trust the help output.

    About Pisa¶

    What is Pisa?¶

    A spec-driven development tool with a generator at its core and a harness around its coding agent. You describe your data and architecture in short text files; Pisa generates a REST API, web pages, tests and build files in Java (Spring Boot), TypeScript (Hono and Prisma) or as a site without a server. See How Pisa works.

    Does Pisa always use a language model?¶

    No. Generating code from your specs is deterministic and needs no model: the same specs give the same code. Only the propose-... commands (except propose-specs), pisa story --specify|--plan|--test|--implement and pisa extend ask one. See Setting up a language model.

    Is the generated code always the same?¶

    Yes, for the same specs and the same Pisa version. pisa replay proves it: it rebuilds a project from its recipe and checks every file against its recorded SHA-256 hash. See Recipe and replay.

    Which kinds of application can Pisa build?¶

    Three targets: Spring Boot (Java), Hono with Prisma (TypeScript), and a single-tier site (HTML and Alpine.js with the data as JSON in the browser). The data model stays the same; only the architecture file (.adl) changes. See Describing your architecture.

    Where do I start?¶

    With the Quick start (ten minutes, no model needed) or a guided tutorial: pisa init, then pisa play.

    Is Pisa ready for production?¶

    Pisa is young. What is missing is in Not yet possible and what was and was not tested in What has and hasn't been tested.

    Generated code and specs¶

    Which files do I write, and which does Pisa write?¶

    You own spec/; Pisa owns .pisa/ and everything it generates under src/. The table of spec files is in The spec files.

    Can I edit the generated files by hand?¶

    Not the ones under src/: they are rewritten on every pisa generate. Change the specs instead, or customize the templates. Files Pisa writes once (for example security.yml, the workflows, a Dockerfile) are yours after the first write.

    Why did my change in src/ disappear?¶

    pisa generate overwrites generated files on each run. Put the change into the spec or into a template.

    Does Pisa ever delete files?¶

    Not silently. It never deletes orphaned files from generate, for example after you rename an entity; you remove them yourself. The one exception: when you change the setup (say from H2 to PostgreSQL), it deletes files the new setup no longer needs, but only if they are still exactly what Pisa wrote, and it prints what it deleted.

    Why does Pisa not overwrite my file?¶

    It never silently overwrites an existing file. --force allows it for most files; a README.md is never overwritten.

    What do I put in Git?¶

    spec/, .pisa/, project.spec.json and README.md. Not target/.

    Why does every entity need an @id?¶

    Every entity has exactly one @id field. See the .dml reference.

    Why are my fields required?¶

    Fields are required by default. Add ? to make one optional; there is no keyword for "required".

    Can I split my model into several files?¶

    Yes. All .dml files in spec/base/ form one model. Put them all there before you generate, or Pisa reports Could not resolve reference.

    Language models¶

    Which model does Pisa use?¶

    Pisa does not pin one. It uses the pi coding agent, which uses the provider and model you have configured. See Setting up a language model.

    Does the model write my code?¶

    No. The generator writes the code from templates. A model proposes specs (a data model, an architecture, form sketches) through a checked tool; Pisa validates the proposal with the same rules as the editor and writes it into a file you can edit. With pisa story --implement the model may write code, but only inside the paths of the plan and the default area of the project (the base package in Spring, src/ in Hono), never a frozen test and never spec/.

    Can the model change my tests?¶

    No. pisa story --test freezes the acceptance tests with a SHA-256 hash, and --check reports a changed or missing file as red.

    What happens when a proposal fails?¶

    After three failed attempts the command exits with code 1 and writes nothing.

    Does Pisa send my files to the model?¶

    propose-model shows the model your description, a short version of the .dml language and the entities of your other .dml files; the other propose-... commands show what they need in the same way. Pisa gives the model fixed instructions: your own pi prompts, AGENTS.md, skills and extensions are not sent.

    I get invalid_grant: Refresh token expired. What now?¶

    Log in again with /login in pi. Other messages from the model provider (workspace id, billing) are in Setting up a language model.

    Running the application¶

    Where are the web page and the API?¶

    http://localhost:8080/ for the pages and http://localhost:8080/api/<entity> for the REST API (paging with ?page=&size=).

    Does the data survive a restart?¶

    With H2 (the Spring default) the data lives in memory and is gone on restart. With SQLite (TypeScript) it is a file; in a container it survives only with the /data volume. With PostgreSQL it lives in the database. A deployment on Render's free tier loses H2 and SQLite data on every restart.

    What do the status codes 400, 401, 403, 405 and 409 mean?¶

    • 400: a required field is missing or a value breaks a rule; the response lists the fields.
    • 401: not logged in.
    • 403: logged in but not allowed (or 403 password change required: the user has not chosen a first password yet).
    • 405: the entity does not allow this operation at all (@operations), even for admins.
    • 409: a unique value already exists.

    How do I run the tests?¶

    Spring: ./mvnw test, browser tests ./mvnw test -Pui, acceptance tests of stories ./mvnw test -Pac. TypeScript: npm test, npm run test:ui, npm run test:ac. Install the browser first with npx playwright install chromium.

    Why do I not see example data?¶

    You need a sampleData block in the .adl. The records are made only when the database is empty, never in the tests and not in the Docker image unless you switch it on. It is not available with PostgreSQL. See Example data.

    Why does my build fail with Package org.h2.tools does not exist?¶

    An old H2 file is left after a switch to PostgreSQL. Delete H2TcpServerConfig.java.

    The Docker build hangs on a Mac. Why?¶

    Docker Desktop's credential helper (docker-credential-desktop get) is stuck. Point DOCKER_CONFIG at a folder whose config.json has no credsStore. See Docker.

    Login and permissions¶

    What are the first user names and passwords?¶

    One starter user per role; the password equals the user name (admin / admin). You must choose a new password at the first login. These passwords are public: use them for development only.

    Where are passwords stored?¶

    As bcrypt hashes in the application's database (table usr_password), never in plain text and never in security.yml.

    How do I add a user?¶

    Edit security.yml and restart the application. A starting password other than the user name needs a bcrypt hash from pisa hash-password.

    Can a role do more than the entity allows?¶

    No. A user's rights are the union of their roles, limited by the entity's @operations.

    Tools and setup¶

    How do I know which tools Pisa needs on my machine?¶

    pisa setup --for <target> checks them: a JDK 17 or newer for Spring Boot, Node.js 24 or newer and npm for TypeScript and for a site without a server. Everything else is optional. See pisa setup and Setup at a glance.

    Does pisa setup install things on my machine?¶

    Only with --install, and only the JDK or Node.js that your target needs and that is missing, with a manager that is already there (SDKMAN, Homebrew, winget, nvm). It shows the command, asks first, never uses administrator rights and never installs Docker, Git or an editor. See pisa setup.

    Do I have to install Maven?¶

    No. The project brings the Maven Wrapper ./mvnw; a JDK is enough (25 by default; 17 and 21 with --java).

    macOS says Pisa "cannot be opened".¶

    That is Gatekeeper. Run xattr -d com.apple.quarantine ~/.bin/pisa. On Windows, SmartScreen: More info, Run anyway.

    The IntelliJ plugin does not find Node.¶

    Set DML_NODE to your Node executable and restart IntelliJ. On Windows this is required. See IntelliJ IDEA.

    The Markdown preview in VS Code says "No PlantUML server".¶

    The Markdown preview cannot render diagrams locally. Run your own PlantUML server or use the public one (your diagrams then go over the internet). See VS Code.

    What are the open points that --specify asks me about?¶

    What your text leaves undecided, as questions the model could not answer itself. At a terminal Pisa asks them (at most five), proposes an answer from its documentation where it is sure, and writes the spec after your Enter. With --no-ask, in CI or without a terminal it does not ask and the points stay under ## Open. See pisa story.

    How do I ask Pisa a question?¶

    pisa ask "<question>" looks it up in the documentation that comes with Pisa and prints the best passages with their source. pisa ask --next says what to do next in the current folder. See pisa ask.

    What does the confidence of pisa ask mean?¶

    high, medium or low says how well the best passage fits the words of your question. It is not a probability. With low the documentation does not answer the question clearly.

    How do I see the options of a command?¶

    pisa <command> --help or pisa help <command>. Help runs nothing.

    Does the guide in doc/ match my Pisa?¶

    Yes: pisa init copies the documents of the Pisa version that made the project into doc/.

    Limits¶

    Can I have several backends or databases?¶

    Not yet. See Not supported in the .adl.

    Which Git hosts and deployment targets are supported?¶

    GitHub for CI, releases and templates, Render for a Docker deployment, GitHub Pages for a single-tier site. The CI, release and pull request files have not been run on GitHub yet; the Pages workflow has. See GitHub CI and releases.

    What can a single-tier site not do?¶

    No login or roles, no docker, no deploy render, and fewer relation forms. It has exactly one container. See Not yet possible.

    Where do I find everything that does not exist yet?¶

    Not yet possible.
