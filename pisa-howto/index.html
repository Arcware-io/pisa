    Pisa How-To¶

    Short answers to "How do I ...?", each with the commands and a link to the part of the User Guide that explains it. Problems and error messages: Troubleshooting and the FAQ. What does not exist yet: Not yet possible.

    If anything here disagrees with pisa --help or pisa <command> --help, trust the help output.

    Install and start¶

    How do I install Pisa?¶

    Run the install script, use Homebrew, or download the file for your system and put it on your PATH. Check with pisa --version. All ways and the file for each system: Installing Pisa.

    How do I update Pisa?¶

    Run the install script again, or download the new file and replace the old one. pisa --version shows which version you run. A project keeps the documents of the version that made it in doc/. See Updating.

    How do I check which tools I am missing?¶

    pisa setup --for hono-prisma     # or spring-boot, alpine-json; inside a project: pisa setup

    Pisa runs the version commands of the tools and says which are there, which are missing or too old, and how to get them. Nothing is written or downloaded. See pisa setup.

    How do I install the missing JDK or Node.js?¶

    pisa setup --for spring-boot --install     # or hono-prisma, alpine-json

    Pisa names the manager it found (SDKMAN, Homebrew or winget for the JDK; nvm, Homebrew or winget for Node.js), shows the exact command and asks before it runs it. --dry-run only shows it, --yes does not ask. Nothing else is installed. See pisa setup.

    What do I need before I generate and run a project?¶

    For Java (Spring Boot) a JDK (25 by default; 17 and 21 work with --java). The project brings the Maven Wrapper ./mvnw, so no Maven is needed. For TypeScript (Hono) Node.js 24. Docker is optional. See Setting up your development environment.

    How do I get a running application in ten minutes?¶

    pisa init --target spring-boot --out ./shop --group ch.example --artifact shop
# write spec/base/shop.dml, then:
cd shop
pisa generate --file spec/base/shop.dml --out .
./mvnw spring-boot:run          # http://localhost:8080/

    Step by step with a model to copy: Quick start.

    How do I follow a guided tour?¶

    mkdir my-project && cd my-project
pisa init          # only doc/ and an empty spec/base/
pisa play          # lists the tutorials

    Three tutorials build the same address book: Spring Boot (Java), Hono (TypeScript) and a site without a server. pisa play spring-java runs one for you (--dry-run shows the steps, --fast skips tests and app start). See pisa play.

    How do I set up my editor?¶

    Install the Pisa plugin for VS Code (a .vsix from the release) or IntelliJ IDEA (a .zip from the release). You get colours, live error checks, formatting and "go to definition" for .dml and .adl files. See Setting up your editor.

    Describe your data¶

    How do I write a data model?¶

    Create a .dml file in spec/base/ and run pisa generate:

    entity Customer {
    @id id: Long
    name: String
    email: String? unique
    oneToMany purchases: Purchase mappedBy customer
}

    The syntax is in the .dml reference. Several .dml files in spec/base/ form one model.

    How do I make a field optional or unique?¶

    Add ? to the type for optional (fields are required by default). Add unique after the type to forbid duplicates: email: Email? unique.

    How do I limit a value (range, length, pattern)?¶

    age: Int(0..150)            // range, bounds inclusive
name: String(1..80)         // length
zip: String ~ "[0-9]{4}"    // pattern; escape a backslash twice

    The rules are checked in the browser, in the API (a 400 with the fields named) and in the generated tests.

    How do I add a fixed list of values?¶

    enum Status { ACTIVE, SUSPENDED ("Blocked"), CLOSED }

    Use it as a field type (status: Status). It becomes a dropdown. The text in parentheses is what the page shows.

    How do I relate two entities?¶

    Use manyToOne, oneToMany ... mappedBy, oneToOne or manyToMany. The side with the database column owns the relation; the other side says mappedBy <field>. Add composed to make the target a part of the entity (saved, edited and deleted with its parent). TypeScript supports fewer relation forms: see Not yet possible.

    How do I stop people from deleting (or creating, or updating) an entity?¶

    Put @operations(create, read, update) above the entity (read is required). The API answers 405 for a forbidden operation and the pages hide the button. Roles are intersected with it. See Restricting what can be done with an entity. To allow everything again, remove the line and run pisa generate.

    How do I name the tables and columns myself?¶

    @table("T_AUTHOR") above the entity and @column("C_NAME") above a field. Use letters, digits and _, not starting with a digit.

    Forms and use cases¶

    How do I change how a form looks?¶

    Edit spec/base/<entity>.ui.md: the PlantUML Salt sketch in it is the layout. Run pisa generate again. If the sketch no longer matches the model, generate stops before it writes anything and names the line. See Form layout.

    How do I get form sketches and use cases without writing them?¶

    pisa propose-specs --out .      # no AI: a .ui.md per entity and one .uc.md

    It only writes missing files. pisa propose-layout --entity <Name> --out . asks a language model for one entity's sketch instead.

    How do I get browser tests for my use cases?¶

    Write the use case in a spec/base/*.uc.md with Form: and Test: lines (or let propose-specs draft them) and run pisa generate. Run them with ./mvnw test -Pui (Spring) or npm run test:ui (Hono).

    Choose the architecture¶

    How do I build in TypeScript instead of Java?¶

    Write runtime hono in the backend container of your .adl, then:

    pisa init --out ./library-ts --adl library.adl
cd library-ts
pisa generate --file spec/base/library.dml --out .
npm install && npm start        # http://localhost:8080/

    See Building in TypeScript instead of Java.

    How do I change the architecture of an existing project?¶

    Edit the .adl, then run pisa init --adl spec/base/<file>.adl --force and pisa generate. Without --force Pisa stops with a message that names the difference. What the .adl can say: Describing your architecture.

    How do I switch from H2 to PostgreSQL?¶

    1. Set engine postgresql for the database in the .adl.
    2. pisa init ... --adl ... --force
    3. pisa generate ...
    4. docker compose up -d

    See Switching from H2 to PostgreSQL.

    How do I get example data in the running application?¶

    Add a sampleData block to the .adl (source faker, entries 1..10, locale "de-CH"), run init --force and generate. The records appear on the first start when the database is empty. Not with PostgreSQL. See Example data.

    How do I build a site without a server?¶

    pisa init --target alpine-json --out ./library --artifact library
cd library && pisa generate --file spec/base/library.dml --out .
npm start                       # http://localhost:8080

    The data is one JSON file kept in the browser; the page can save and load it. package zip makes a ZIP of the site (npm run package). See A single-tier site.

    How do I publish a site without a server on GitHub Pages?¶

    Put pipeline { release github deploy pages } and scm { host github } in the .adl. A tag v* then runs .github/workflows/pages.yml. The one-time GitHub setup (a public repository, switching Pages on) is described under GitHub Pages.

    How do I make my own templates?¶

    pisa eject-templates --target spring-boot --out ./shop
# edit .pisa/templates/spring-boot/..., then:
pisa generate --file spec/base/shop.dml --out ./shop

    Only the files you keep override the built-in ones. See Customizing templates.

    Login, users and roles¶

    How do I turn on login?¶

    Add authentication session to the backend container (and optionally a roles { ... } block), then run init --force and generate. Pisa writes security.yml, a login page and a change-password page. See Adding login, users and roles.

    How do I sign in the first time?¶

    Each starter user's password is the user name (admin / admin, user / user). You must choose a new password on the change-password page. These passwords are public: development only.

    How do I add a user or a role?¶

    Edit security.yml and restart the application, no generate needed. For a starting password other than the user name run pisa hash-password and paste the hash into a password: field.

    How do I limit a role to some operations?¶

    roles {
    ADMIN
    USER {
        Company: read, update
    }
}

    A role's rights are limited by the entity's @operations.

    How do I reset a forgotten password?¶

    Delete the user's row from the table usr_password. With the in-memory H2 database the table empties on every restart anyway.

    How do I turn login off again?¶

    Remove the line from the .adl, run init --force, then generate. Pisa deletes the login files it created, unless you changed them (then it prints the rm command). security.yml stays yours.

    Docker, CI, releases and deployment¶

    How do I get a Dockerfile?¶

    Add a docker block to the .adl (add compose for a compose.yml; with PostgreSQL you always get one). Then docker compose up --build. See Docker.

    How do I run the tests on every push?¶

    Put pipeline { ci github } in the .adl. Pisa writes .github/workflows/ci.yml with a job for the fast tests and one for the browser tests. See GitHub CI and releases.

    How do I publish a release?¶

    Put release github in the pipeline block. Then git tag v1.0.0 && git push origin v1.0.0 runs the tests and creates a GitHub release with generated notes.

    How do I get a pull request template and issue forms?¶

    Add scm { host github } (see the guide for the lines that go with it). GitHub is the only supported host.

    How do I put my project into a Git repository?¶

    If the .adl has a pipeline or scm block, or you pass --git, pisa init creates a local repository with a first commit. It never pushes. Then gh repo create <name> --private --source . --push (needs gh auth login), or git remote add origin ... and git push -u origin main. See Git repository.

    How do I deploy to Render?¶

    Add deploy render to the pipeline (it needs the docker block), push to GitHub, create a Blueprint on Render with render.yml, save the deploy hook as the secret RENDER_DEPLOY_HOOK_URL, and push a tag. The free tier sleeps when idle and keeps no data on H2 or SQLite. See Deploying to Render.

    Use a language model¶

    Do I need a language model?¶

    Only for the commands that ask one: the propose-... commands (not propose-specs), pisa story --specify|--plan|--test|--implement, and pisa extend. Everything that generates code works without one. See Setting up a language model.

    How do I set up a language model?¶

    Pisa uses the pi coding agent. Start pi, type /login and pick a provider (Anthropic, for example), or use an API key. Your own pi prompts, AGENTS.md, skills and extensions have no effect on Pisa's steps.

    How do I get a data model from a description?¶

    Write what you want in spec/base/domain-spec.md (or one spec/base/requirements.md for everything), then:

    pisa propose-model --out .

    Pisa checks the answer with the same validator as the editor and writes spec/base/<name>.dml. Read it before you generate. It never overwrites an existing file unless you pass --force.

    How do I get an architecture from a description?¶

    pisa propose-architecture --out .       # reads spec/base/architecture.md or requirements.md
pisa init --adl spec/base/architecture.adl --out .

    What if a proposal fails?¶

    After three failed attempts the command exits with code 1 and writes nothing. Run it again, or write the file yourself.

    Change a running application¶

    How do I clear the open points of a spec?¶

    When you run pisa extend --specify "<wish>" or pisa story --specify "<sentence>" at a terminal and the model leaves open points, Pisa asks them one by one, proposes an answer from its documentation where it is sure (Enter takes it), has the model work the answers in, and writes the spec after your Enter. Then it asks Continue with --plan? [Y/n]. --no-ask skips the dialog and leaves the points under ## Open. See pisa story.

    How do I make a change as a story?¶

    pisa story --specify "User can log in"   # a story with acceptance criteria AC1..ACn
pisa story --plan                        # 02-plan.md
pisa story --test                        # 03-test.md: freezes the acceptance tests
pisa story --implement                   # run it twice: assignment, then implementation
pisa story --check                       # runs the tests, writes 05-check.md

    Name the feature yourself with --feature 001. See Changing your application.

    How do I see which stories are done?¶

    pisa story --list shows all stories with a check mark or a cross. pisa story --check --full runs every story and prints a summary.

    How do I run the acceptance tests?¶

    Only on demand: ./mvnw test -Pac (Spring) or npm run test:ac (Hono). The normal build does not run them. The CI only checks that every story with a plan has a report without failures.

    Why may the language model not change my tests?¶

    pisa story --test freezes the test files with a SHA-256 hash. --check compares the hashes; a changed or missing file is red however green the tests are.

    Keep a project healthy¶

    How do I update the library versions?¶

    pisa update-versions --out . --check build

    Pisa finds the newest stable versions, tries them on a copy and writes the ones that pass into the versions block of the .adl. Versions stay fixed until you run it again. Needs a network. See pisa update-versions.

    How do I prove a project can be rebuilt from its specs?¶

    pisa replay --from ./shop --out ./shop-copy

    It ends with All N generated file(s) match the hashes recorded in the recipe. See Recipe and replay.

    What should I commit to Git?¶

    spec/, .pisa/, project.spec.json and README.md. Not target/.

    How do I find an answer in the documentation?¶

    pisa ask "how do I turn on login?"      # the best passages with their source
pisa ask --next                          # what to do next in this folder

    Pisa looks the question up in this documentation (no model, nothing written) and says how sure it is: high, medium or low. A German question works for the common words. See pisa ask.

    How do I find out what a command can do?¶

    pisa --help for the overview, pisa <command> --help (or pisa help <command>) for one command. Help runs nothing.

    Work with other tools¶

    How do I let an AI agent call Pisa?¶

    claude mcp add pisa -- pisa mcp

    pisa mcp starts an MCP server (stdio) with four tools: generate, parse_domain_model, and the read-only lookup_docs (answers a question from this documentation, with sources) and project_status (what to do next in a project folder). By hand it looks idle: that is normal. See pisa mcp.

    How do I preview the class diagram of my model?¶

    Install PlantUML and Graphviz (see Installing PlantUML and Graphviz), and use the Pisa plugin: every time you save a .dml file it draws a class diagram.
